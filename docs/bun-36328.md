# Bun #36328: atomic-save regression

This case study demonstrates a runtime watcher regression using an incremental cache and independent disk hashes. It preserves the distinction between notification evidence and the consumer-state verdict.

## Upstream regression

- [Original issue](https://github.com/oven-sh/bun/issues/36328): Bun **1.3.14**, revision **0d9b296a**, Linux **7.0.0-28-generic x86_64**. It reports missing destination-named notifications after a write-then-rename atomic save.
- [Release metadata for bun-v1.3.14](https://github.com/oven-sh/bun/releases/tag/bun-v1.3.14): revision **0d9b296af33f2b851fcbf4df3e9ec89751734ba4**, published 2026-05-13.
- [Upstream investigation](https://github.com/oven-sh/bun/issues/36328#issuecomment-5113708588): reproduces on 1.3.14 and reports success on **1.4.0 canary**, including main debug build **59242d6c891b576c55b61bfff823ae9e55b8648e**.
- [PR #31830](https://github.com/oven-sh/bun/pull/31830), merged 2026-06-19 as [`dae2e8722b67c39a9d483ed7ef3f4ca662c3894b`](https://github.com/oven-sh/bun/commit/dae2e8722b67c39a9d483ed7ef3f4ca662c3894b). Its `src/runtime/node/path_watcher.rs` and `win_watcher.rs` changes replace duplicate suppression that required both path and event-type differences with a predicate that emits when either differs. Thus distinct names within one millisecond are no longer incorrectly suppressed as duplicates. The change addresses the reported atomic-save destination loss; it does not establish correctness for all watcher races.

## Recorded reproduction

The [probe source](../scripts/bun-36328.mjs) is identical for both runtimes. SHA-256 of that source when the recorded results were produced:

```text
a66d87e4fa8519fa7b1105b0908cbc984dafd1bd5c2849c369afd6e4a6d4da0d
```

The probe runs a real directory `fs.watch`, maintains a filename-directed cached index, performs a synchronous temporary-file write and rename over an existing file, then independently enumerates/hashes the disk. Snapshot observations read the cache without repair. After writes stop, it samples for up to 700 ms at 50 ms intervals; the first equal sample ends a trial. Each trial creates and removes its own temporary tree. No event is injected, filtered to simulate the bug or artificially dropped. A null filename cannot update a named path in this deliberately simple consumer; all notifications remain in the evidence.

Execution environment: Docker Linux **arm64**, kernel **7.0.14-linuxkit**. Containers had no network, read-only root filesystems, no Linux capabilities, read-only probe mounts and a writable temporary tmpfs. These restrictions apply to this reproduction environment, not to arbitrary user adapters in WatchConverge.

- **Bun 1.3.14**, actual runtime revision `0d9b296af33f2b851fcbf4df3e9ec89751734ba4`: **10/10 DIVERGED**. Every trial retained the v0 content hash while disk held v1. Observed notifications named only `app.tsx.tmp`; destination-named notifications were absent in these trials. Exit **1**. [Raw results](evidence/bun-1.3.14-linux-arm64.json).
- **Bun 1.4.0 release**, actual runtime revision `34cbb9a40b4bd1bd767d134a7065e66c2432a676`: **10/10 PASS**. Cached and disk SHA-256 values matched. Destination-named notifications were observed in these trials. Exit **0**. [Raw results](evidence/bun-1.4.0-linux-arm64.json).

The state comparison determines the verdict; `destinationNamed` is diagnostic evidence, not a requirement imposed by the tool. These results do not establish a fixed notification sequence, success probability under arbitrary scheduling or the earliest fixed Bun release. The original x86_64 kernel and exact upstream canary/debug binary were not reproduced.

### Repeat using the recorded immutable images

Run from the repository root. The digests below are the tested arm64 images; an x86 host needs arm64 container support/emulation, or should use version tags for a separately documented native-architecture experiment.

```sh
docker run --rm --platform linux/arm64 --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges --memory 256m --cpus 1 \
  --tmpfs /tmp:rw,noexec,nosuid,size=32m \
  --mount "type=bind,source=$PWD/scripts/bun-36328.mjs,target=/probe.mjs,readonly" \
  oven/bun@sha256:e10577f0db68676a7024391c6e5cb4b879ebd17188ab750cf10024a6d700e5c4 \
  bun /probe.mjs
# Expected exit 1: ten stale-index trials on the old implementation.

docker run --rm --platform linux/arm64 --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges --memory 256m --cpus 1 \
  --tmpfs /tmp:rw,noexec,nosuid,size=32m \
  --mount "type=bind,source=$PWD/scripts/bun-36328.mjs,target=/probe.mjs,readonly" \
  oven/bun@sha256:5ff609364c049b54eb0ff560ec96319729a972078ef2c755d758f0c6ef89c2d6 \
  bun /probe.mjs
# Expected exit 0: ten matching-index trials on the fixed release.
```

Docker may need to download the images before launching the network-disabled containers. The probe itself only writes its owned temporary directories. To test a locally installed Linux Bun without Docker, run `bun scripts/bun-36328.mjs` and record the printed runtime revision and platform. A non-Linux/non-Bun invocation returns UNSUPPORTED with exit 4; it is not PASS.
